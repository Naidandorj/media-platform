# Save or resume a project

Read AGENTS.md, README.md, and the relevant project's BRIEF.md and HANDOFF.md. Resolve ambiguous project identity before modifying files. Projects/Project-Template is empty scaffolding, never an actual project to resume.

## Save a milestone

Write briefs and handoffs in the owner's chosen language (see AGENTS.md "Language"); keep file names and headings as they are.


Update the existing handoff with:

- Actual update date, current status, and any relevant environment or device.
- Completed work and real output locations.
- Confirmed decisions and task-specific feedback.
- Pending work, unresolved questions, blockers, and next step.
- What was reviewed, tested, saved, or delivered and what remains unverified.

Preserve user edits and useful prior decisions. Keep the current summary short and accurate. Distinguish planned, drafted, reviewed, approved, tested, and delivered work. A draft is not an approval or publication. Link to context and source files instead of repeating them in full. Do not invent paths, test outcomes, or timestamps.

If a significant decision changes requirements, update the brief as well. Archive long history only when needed and without removing information the user still relies on. Verify saves and summarize the handoff location.

## Resume safely

Read the handoff and inspect relevant current files before saying where the project stands. Check that external sources and tool connections are available in this session. A handoff's recorded access does not establish current access.

Summarize the current state and identify the next step. Continue the user's requested work when authorized. If the user only asks for status, give status instead of running all pending tasks. Missing data, approval checkpoints, or changed requirements may require a focused question.

When transferring to another app, tell it to read the brain's starting instructions and this handoff. Do not claim chat history, account connections, installed skills, or schedules moved wit
h the folder.
